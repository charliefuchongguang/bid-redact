## 2. 规则库 v1.1 的关键修正

1. **WL-01 不再吞身份证**：18 位串先做 GB11643 校验，能通过身份证校验则不走白名单。
2. **姓名白名单收窄**：`2~4 汉字` 必须同时命中“姓名/法定代表人/联系人”等上下文。
3. **校验位命名**：`luhn_id` → `gb11643`。
4. **手机号全遮**。
5. **公章**：默认不整框跳过；仅 `protect_seal: true` 的规则在红像素占比超阈值时跳过。
6. **新增规则**：大写金额、开户行、基本存款账户编号、银行回执凭证号/验证码、保证金、年度营业额、合同保密条款、招标限价白名单。
7. **YAML 键 `on` 加引号**：避免 YAML 1.1 把 `on` 解析成布尔 True；加载器同时做了兼容归一化。

## 3. OCR 归一化（扫描页关键）

Mineru OCR 文本存在：

- 全角标点：`：￥1，292，072.30`
- 字符间空格：`l i s i @e x a mp l e . c o m`
- 全角字母数字

处理方式：`normalize_ocr_text()` 统一转半角、去空白，并保留“归一化字符 → 原始下标”映射。匹配在归一化文本上进行，遮蔽框仍按原始下标映射回页面坐标。

## 4. 遮蔽流程

```
收集 Box → 红章检测 → add_redact_annot(fill=黑)
→ apply_redactions(images=PDF_REDACT_IMAGE_PIXELS)
→ 150dpi 纯黑占比自检（≥98%）
   ├─ 失败：从源文件重载、外扩 1.5 倍重试（最多 3 次）
   └─ 通过：逐格绘制中性灰马赛克
→ save(garbage=4, deflate=True, clean=True)
```

- 自检失败仍无法通过 → 标记「待人工」，不阻断整体。
- 红章重叠且规则要求保护 → `state=skipped_seal`，不遮蔽。

## 6. CLI 用法

```powershell
cd backend
..\.venv\Scripts\python.exe -m app.cli 输入.pdf -o 输出.pdf --mineru auto
```

参数：

| 参数 | 说明 |
|---|---|
| `--mineru auto\|on\|off` | 默认 auto：有扫描页才调用 |
| `--rules` | 规则库路径，默认 `rules/rules.yaml` |
| `--no-seal-guard` | 关闭红章重叠跳过 |
| `--report` | 报告 JSON 路径 |

报告包含：页类型、命中规则统计、每个 Box 的页码/坐标/规则/状态/哈希、自检明细、耗时。

## 7. 已知限制（待真实样本校准）

1. **扫描页表格**：Mineru content_list 不提供单元格 bbox，当前按等宽网格近似，置信度 0.65，状态 `pending`；需真实表格样本校准。
2. **全页扫描中的身份证**：依赖 Mineru 返回的 `image` 块或页面图片；若整页是一张图且未切出卡片区域，卡片扩展只能覆盖号码本身。
3. **红章阈值**：当前 `red_ratio_skip=0.10`，真实印章需用样本校准（合成细线圆章仅 0.058）。
4. **证件照/二维码/开户许可证整证**：规则未完全覆盖，需样本确认版式。
5. **OCR 空格**：归一化会去掉英文单词间空格，当前规则不受影响；如后续需按英文句子定位，应改为“仅去除数字/邮箱/证件号内部空格”。
6. **性能**：马赛克为矢量小矩形，大框已用 `max_tiles=4000` 限流；超大文件仍需实测。
