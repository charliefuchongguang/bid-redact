## 5. InsightFace 当前实现细节

### 5.1 模型

- 已安装 `insightface==2.1`
- 模型：`data/models/insightface/det_10g.onnx`
- 模型包：`buffalo_l`
- 模型文件不提交仓库，`data/` 已 gitignore。
- 用户已确认取得 InsightFace 预训练模型授权。
- 下载脚本支持 buffalo_l / buffalo_sc，并校验 SHA256。

### 5.2 当前配置

```env
FACE_DETECTION_ENABLED=true
FACE_MODEL_PATH=./data/models/insightface/det_10g.onnx
FACE_DETECT_DPI=150
FACE_DET_SIZE=640
FACE_DET_THRESH=0.5
FACE_MIN_SIZE_PT=18
FACE_PAD_RATIO=0.12
FACE_TILE_SIZE=0
FACE_SCAN_MODE=image_pages
FACE_REPLACE_ID_AVATAR=true
FACE_FAIL_POLICY=fail
FACE_CTX_ID=-1
FACE_ORT_THREADS=0
```

### 5.3 行为

- 只扫描含图片/扫描页；
- 150 DPI 整页检测；
- 模型/单页检测失败 → 任务失败；
- 人脸框 `FACE-01`，`category=personal`，`source=insightface`；
- 人脸检测先于规则定位执行：
  - `faces_by_page` 传给 `locate()`；
  - `image_matcher` 用“是否有脸”判断身份证正面/背面；
  - 有人脸 + 身份证字段 → 正面：生成头像/号码框；
  - 无人脸 + 身份证上下文 → 背面：遮底部整条（`id_card_back` / `id_card_back_inferred`）；
  - 毕业/学位/职称/注册证书照片按文本与面积特征排除，不再误判为身份证正面；
  - 定位后删除所有 `id_card_avatar` 框，P5 只保留号码框；
- 结果缓存：`data/faces/cache/{sha}.{digest}.json`；
- 缓存不含图片，只有坐标。

### 5.4 已知限制

- 极小/低清人脸（如网页截图缩略头像）可能漏检；
- `FACE_TILE_SIZE=1024` 可尝试分块提升召回，但会增加 CPU；
- 如果正面人脸漏检且卡片无文本层，可能被当作背面遮底部；有 `公民身份号码/住址/民族` 等 OCR 字段时仍可判定为正面。

## 8. 重要编码/文件操作教训

- **不要用 PowerShell 的 `Get-Content` / `Set-Content` 重写含中文的 `.py` / `.md` / `.env` 文件**：
  - PowerShell 5.1 默认按 ANSI 读取无 BOM 的 UTF-8 文件；
  - 会把中文变成乱码，甚至产生语法错误。
- 修改文件请使用编辑工具（read/edit/write），不要用 PowerShell 做内容替换。
- 如果必须批量处理编码，请用 Python 读写并指定 `encoding="utf-8"`。
- 新增 `.py` / `.md` 文件后检查没有 BOM、没有 `U+FFFD` 替换字符。
- 不要提交 `.env`、`data/`、模型文件、`node_modules/`。
