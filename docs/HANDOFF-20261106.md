\## 6. P1：SQLite 迁移



\### 6.1 类型与模型映射



| MySQL | SQLite / SQLAlchemy | 说明 |

|---|---|---|

| BIGINT AUTO\_INCREMENT | Integer 主键 | SQLite 只有 `INTEGER PRIMARY KEY` 自增 |

| BIGINT 外键 | Integer | 与主键一致 |

| BOOLEAN | Boolean | 存 0/1 |

| DATETIME | DateTime | 用 Python `default=datetime.now` / `onupdate=datetime.now` |

| DOUBLE | Float | REAL |

| VARCHAR(n) | String(n) | 长度不强制 |

| TEXT | Text | — |

| utf8mb4 / InnoDB | 删除 TABLE\_ARGS | SQLite 不需要 MySQL 方言参数 |

| ON UPDATE CURRENT\_TIMESTAMP | SQLAlchemy `onupdate` | SQLite 不原生支持 |



\### 6.2 必须修改的文件



| 文件 | 改动 |

|---|---|

| `backend/app/core/config.py` | 默认 `DATABASE\_URL=sqlite:///.../data/app.db` |

| `backend/app/db/session.py` | SQLite engine、`check\_same\_thread=False`、WAL、FK、busy\_timeout |

| `backend/app/db/models.py` | BigInteger→Integer；删除 TABLE\_ARGS；时间默认值；规则表后续新增 |

| `backend/app/db/init\_db.py` | 建表 + 种子 admin；P2 再种子规则 |

| `backend/app/services/worker.py` | 删除 `FOR UPDATE SKIP LOCKED`；普通 SELECT + UPDATE |

| `backend/app/api/admin.py` | 取消 `\_queue\_reprocess` 的队列逻辑（P4 改为同步） |

| `backend/scripts/check\_db.py` | 改 SQLite 版本/表查询 |

| `backend/scripts/migrate.py` | 删除或改 `PRAGMA table\_info` |

| `backend/requirements.txt` | 移除 `pymysql`、`cryptography`（确认无其他用途） |

| `.env` / `.env.example` | `DATABASE\_URL=sqlite:///.../data/app.db` |

| `deploy/docker-compose.yml` | 去掉 MySQL 依赖，保留 data 卷 |

| `deploy/Dockerfile.api` | 不装 MySQL 驱动 |

| `README.md` / `docs/部署手册.md` | 删除 MySQL，补 SQLite 备份/恢复 |

| 测试 | 使用临时 SQLite 文件 |



\### 6.3 SQLite 会话配置



```python

engine = create\_engine(

&#x20;   settings.database\_url,

&#x20;   connect\_args={"check\_same\_thread": False, "timeout": 30},

&#x20;   pool\_pre\_ping=True,

)



@event.listens\_for(engine, "connect")

def \_sqlite\_pragma(conn, \_):

&#x20;   cur = conn.cursor()

&#x20;   cur.execute("PRAGMA journal\_mode=WAL")

&#x20;   cur.execute("PRAGMA foreign\_keys=ON")

&#x20;   cur.execute("PRAGMA busy\_timeout=5000")

&#x20;   cur.execute("PRAGMA synchronous=NORMAL")

&#x20;   cur.close()

```

\## 8. P3：官方 MinerU 精准解析



\### 8.1 模式



\- 必须精准解析；

\- 轻量解析只返回 Markdown，10MB/20 页，无 bbox，不可用。



\### 8.2 调用流程



```http

POST https://mineru.net/api/v4/file-urls/batch

Authorization: Bearer <token>

Content-Type: application/json



{

&#x20; "files": \[

&#x20;   {"name": "bid.pdf", "data\_id": "file-123", "is\_ocr": true, "page\_ranges": "1-200"}

&#x20; ],

&#x20; "model\_version": "pipeline",

&#x20; "enable\_table": true,

&#x20; "enable\_formula": false,

&#x20; "language": "ch"

}

```



返回 `batch\_id` + `file\_urls`，然后 `PUT` 上传 PDF；轮询：



```http

GET https://mineru.net/api/v4/extract-results/batch/{batch\_id}

```



完成后下载 `full\_zip\_url`，解压：



\- `\*\_content\_list.json`

\- `layout.json`（middle.json）

\- `full.md`

\- 图片资源（不需要，删除）



\### 8.3 参数



```env

MINERU\_PROVIDER=official

MINERU\_API\_TOKEN=<token>

MINERU\_MODEL\_VERSION=pipeline

MINERU\_IS\_OCR=true

MINERU\_ENABLE\_TABLE=true

MINERU\_ENABLE\_FORMULA=false

MINERU\_LANGUAGE=ch

MINERU\_SPLIT\_PAGES=200

MINERU\_KEEP\_IMAGES=false

```



\### 8.4 分片



\- 单文件 >200 页或 >200MB：本地拆分；

\- 每片独立提交；

\- 合并时给 `page\_idx` 加偏移；

\- 921 页示例拆 5 片。



\### 8.5 结果解析



\- 同时支持 `content\_list.json` 和 `layout.json`；

\- \*\*自动判断 bbox 空间\*\*：

&#x20; - `max\_x ≤ page\_width\*1.05` 且 `max\_y ≤ page\_height\*1.05` → 页面 point；

&#x20; - 否则 → 0\~1000 归一化；

\- 官方 3.4.4 的 JSON 是页面 point；内部 router 曾是 0\~1000，必须两种都支持。



\### 8.6 删除内部 router



\- 不保留内部 MinerU 服务；

\- 官方失败时重试/标记失败，不降级；

\- 错误码：A0202/A0211 Token、-60005 大小、-60006 页数、-60009 队列满、-60018 每日上限。



\### 8.7 合规



上线前定稿 `docs/第三方数据处理与合规说明.md`，内容见对话中的草稿。



\### 8.8 P3 验收



\- 用 `testdata/扫描型3.pdf`（34 页）跑通；

\## 10. P5：身份证只遮头像 + 号码



已从 `扫描型3.pdf` 分析：



\- 官方 JSON bbox 是页面 point；

\- 正面身份证图块示例：`\[74,159,283,289]`，209×130，比例 1.61；

\- 头像连通域：

&#x20; - 法定代表人：`\[200,181,263,258]`，相对卡片 x 60%–90%，y 17%–76%；

&#x20; - 授权代表：`\[206,422,268,498]`，相对 x 63%–92%，y 20%–75%；

\- 号码在 JSON 中无 OCR 文本，需要 OCR/模板兜底。



方案：



1\. 卡片定位：Mineru image 块 + 宽高比筛选；双卡按 50% 拆分；

2\. 头像：连通域检测（推荐）或模板 `x 0.59–0.93, y 0.15–0.80`；

3\. 号码：底部区域 `x 0.06–0.98, y 0.78–0.99`，OCR 识别 18 位并 GB11643 校验；失败则遮整条底部；

4\. 输出两个 `rect` Box，不再输出整卡；

5\. 失败回退整卡，标记 `needs\_review`；

6\. 可选依赖：OpenCV + RapidOCR；如不引入，使用模板版。



注意：只遮头像+号码后，姓名、地址、出生日期仍可见，需业务/合规确认。

\## 11. 关键风险



| 风险 | 对策 |

|---|---|

| BigInteger 不自增 | 全部改 Integer |

| MySQL 方言参数 | 删除 TABLE\_ARGS |

| `FOR UPDATE SKIP LOCKED` | 单 worker 普通查询 |

| SQLite 写锁 | WAL + busy\_timeout + 重试 |

| 时间时区 | Python `datetime.now` |

| bbox 空间不一致 | 自动判断页面 point / 0\~1000 |

| 官方 Token 泄露 | 只放 `.env`，上线后轮换 |

| 921 页超限 | 本地拆分 + 页码偏移 |

| 官方服务不可用 | 重试，失败标记，不降级内部 |

| 规则发布影响旧文件 | 只影响新文件 |

| 规则原始 JSON/YAML 非法 | 服务端解析 + 校验后保存 |
