# 部署手册

> 目标服务器：公司内部服务器
> 访问域名：`tuomin.bjzcc.cn`
> 交付形态：Docker Compose（API + Nginx 静态站点），SQLite 单文件数据库

## 1. 前置条件

| 项 | 要求 |
|---|---|
| 操作系统 | Linux，已安装 Docker 24+ 与 Docker Compose v2 |
| 域名 | `tuomin.bjzcc.cn` 的 A 记录指向本服务器 |
| 证书 | `fullchain.pem`、`privkey.pem`（放到 `deploy/cert/`） |
| 数据库 | 无需外部数据库；SQLite 文件 `data/app.db` 随 data 卷持久化 |
| 网络 | 服务器可访问 `https://mineru.net`（MinerU 官方 API）；模型可离线拷贝 |
| 人脸模型 | `data/models/insightface/det_10g.onnx`（已取得 InsightFace 模型授权） |
| 磁盘 | 预留 ≥ 50GB（原件 + 脱敏件 + MinerU/人脸缓存 + 模型） |

## 2. 目录结构

```
bid-redact/
├─ backend/           API 源码
├─ frontend/          Vue3 源码
├─ rules/             规则库
├─ deploy/
│  ├─ Dockerfile.api
│  ├─ Dockerfile.web
│  ├─ docker-compose.yml
│  ├─ nginx.conf
│  ├─ .env.example
│  └─ cert/           fullchain.pem / privkey.pem
├─ data/              运行数据（挂载）
│  ├─ original/       原 PDF
│  ├─ redacted/       脱敏件
│  ├─ mineru/         MinerU 结果缓存
│  ├─ logs/           报告与日志
│  └─ app.db          业务 + 规则数据库（SQLite）
└─ docs/
```

## 3. 部署步骤

### 3.1 上传代码

把整个 `bid-redact/` 上传到服务器，例如 `/opt/bid-redact`。

### 3.2 配置环境变量

```bash
cd /opt/bid-redact/deploy
cp .env.example .env
vi .env
```

必须修改：

- `LOCAL_FULL_ACCESS=true`：本地部署让所有登录用户拥有完整权限；服务器多用户部署改为 false
- `DATABASE_URL=sqlite:////app/data/app.db`
- `SECRET_KEY`：随机长字符串（`openssl rand -hex 32`）
- `MINERU_API_TOKEN`：MinerU 官方 API Token（只放 `.env`，不要提交仓库）
- `FACE_MODEL_PATH=/app/data/models/insightface/det_10g.onnx`
- `FACE_DETECTION_ENABLED=true`（模型未就绪时先设为 false）
- `ADMIN_PASSWORD`：初始化管理员密码
- `CORS_ORIGINS=https://tuomin.bjzcc.cn`

设置权限：

```bash
chmod 600 .env
```

### 3.3 放置证书

```bash
mkdir -p cert
cp /path/fullchain.pem cert/
cp /path/privkey.pem cert/
chmod 600 cert/*
```

### 3.4 准备人脸模型

在部署目录执行（容器内下载，写入挂载的 data 卷）：

```bash
cd /opt/bid-redact/deploy
docker compose run --rm api python -m scripts.download_face_model --pack buffalo_l --accept-license
```

脚本会下载官方模型包并只提取 `det_10g.onnx` 到 `data/models/insightface/`。离线服务器可直接拷贝该 ONNX 文件并校验 SHA256。模型文件不提交仓库，通过 `../data:/app/data` 挂载进容器。

### 3.5 初始化数据库

```bash
docker compose build api
docker compose run --rm api python -m app.db.init_db
```

输出 `admin: id=1 username=admin created=True` 即成功。

若数据库是已有旧版本，再执行一次迁移（幂等）：

```bash
docker compose run --rm api python -m scripts.migrate
```

> `create_all` 只建缺失的表，不会修改已有表结构；因此旧库需要 `migrate` 补充新增列。

### 3.6 启动服务

```bash
docker compose up -d --build
docker compose ps
```

访问：

- 前端：`https://tuomin.bjzcc.cn`
- 健康检查：`https://tuomin.bjzcc.cn/api/health`
- 接口文档：`https://tuomin.bjzcc.cn/api/docs`（FastAPI 默认挂在 `/docs`，如需外部访问需额外放开）

### 3.7 首次登录

使用 `.env` 中的 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 登录，进入「管理后台」。
建议首次登录后立即修改管理员密码（当前版本通过重新生成哈希或后续账号管理功能实现）。

## 4. 日常运维

### 4.1 日志

```bash
docker compose logs -f api
docker compose logs -f web
tail -f data/logs/*.log
```

### 4.2 备份

必须备份：

```bash
# 数据库（先做 WAL 检查点，再备份单文件）
docker compose exec -T api python -c "import sqlite3; c=sqlite3.connect('/app/data/app.db'); c.execute('PRAGMA wal_checkpoint(TRUNCATE)'); c.close()"
cp data/app.db backup_app_$(date +%F).db

# 文件
tar czf data_$(date +%F).tar.gz data/original data/redacted
```

### 4.3 更新规则库

1. 管理员进入「管理后台 → 规则库」；
2. 基于 active 版本「创建草稿」，编辑 JSON 或 YAML；
3. 「校验」通过后「保存草稿」，再「发布」为 active；
4. 发布只影响新上传文件，已有文件保留原规则版本；
5. 需要回退时，在版本历史中选中历史版本点「回滚」。

建议规则变更前先「导出 YAML」备份，并用文本试跑验证。

### 4.4 更新程序

```bash
# 覆盖代码后
docker compose up -d --build
```

### 4.5 清理 Mineru / 人脸缓存

- MinerU：`data/mineru/cache/`，按文件 sha256 + 解析参数命名（`*.official-*.json`），仅保存 JSON。
- 人脸：`data/faces/cache/`，按文件 sha256 + 模型/DPI/阈值参数命名，仅保存坐标 JSON。

磁盘紧张时可清理不再使用的缓存；清理后重新处理会再次调用 MinerU/InsightFace。

## 5. 常见问题

| 现象 | 排查 |
|---|---|
| 502 Bad Gateway | `docker compose logs api`，确认 API 启动、`data/app.db` 可读写 |
| 上传 413 | Nginx `client_max_body_size` 与 `MAX_UPLOAD_MB` 是否一致 |
| 文件一直排队 | 检查 worker 是否启动（日志 `worker started`）；MinerU 队列是否拥堵 |
| 扫描件处理失败 | 检查 `MINERU_API_TOKEN` 是否有效、`mineru.net` 是否可访问、每日页数是否超限 |
| 人脸检测失败 | 检查 `FACE_MODEL_PATH` 是否存在、模型授权、`requirements-face.txt` 是否安装 |
| 人脸检测过慢 | 降低 `FACE_DETECT_DPI`，或使用 `buffalo_sc` 的 `det_500m.onnx`；小脸多时再开启 `FACE_TILE_SIZE` |
| MinerU 报连接失败 | 服务器能否访问 `mineru.net`；Token 是否有效 |
| 数据库 locked | 确认单实例部署，检查 `data/app.db-wal` 与磁盘空间 |
| 预览空白 | 检查 `data/redacted/{id}.pdf` 是否存在、API 用户是否有权限 |

## 6. 安全要求

1. 全站 HTTPS，HTTP 自动跳转。
2. `.env`、`cert/` 权限 600，不入库、不打包。
3. `data/app.db` 权限 600，备份需包含 WAL 检查点。
4. `data/` 不放入 Nginx 静态目录，只能通过 API 鉴权访问。
5. 普通用户仅可访问本人文件；管理员可访问全部。
6. 定期审计 `tm_audit_logs`（当前版本已建表，登录/上传/下载审计可在 V1.1 补齐）。
7. 原 PDF 与脱敏件均为敏感数据，备份介质需加密。
8. InsightFace 模型文件不入库；仅使用已授权的模型，并在合规文档中留存授权记录。

## 7. 回滚

```bash
docker compose down
# 恢复上一版代码
docker compose up -d --build
# 如数据库结构变更，使用备份的 app.db 恢复
```
